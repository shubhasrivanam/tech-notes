## What is SSH?

SSH (Secure Shell) is a protocol for securely accessing and managing remote
machines over an unsecured network. It encrypts the entire session — commands,
output, and any file transfers — so nothing is sent in plaintext.

## How the Connection Works

1. **TCP handshake** — client connects to the server, typically on port 22
2. **Key exchange** — client and server agree on a shared session key using
   asymmetric cryptography (Diffie-Hellman), without ever sending the key itself
3. **Server authentication** — client verifies the server's host key against
   its known_hosts file, to prevent man-in-the-middle attacks
4. **User authentication** — via password or (preferably) public/private key pair
5. **Encrypted session begins** — all further traffic is symmetrically encrypted

## Key-Based Authentication (the secure way)

​```bash
# Generate a key pair
ssh-keygen -t ed25519 -C "your_email@example.com"

# Copy your public key to the remote server
ssh-copy-id user@remote-host

# Now you can log in without a password
ssh user@remote-host
​```

Your **private key** stays on your machine and is never transmitted.
Only the **public key** is placed on the server (in `~/.ssh/authorized_keys`).
The server challenges your client to prove it holds the matching private key —
this is what actually authenticates you.

## Useful SSH Config Shortcuts

Add to `~/.ssh/config` to avoid typing long commands every time:

​```
Host myserver
    HostName 192.168.1.10
    User shubha
    Port 22
    IdentityFile ~/.ssh/id_ed25519
​```

Then just run:
​```bash
ssh myserver
​```

## SSH Tunneling (bonus use case)

SSH isn't just for shell access — it can forward ports too:

​```bash
# Local port forwarding: access a remote DB as if it's local
ssh -L 5432:localhost:5432 user@remote-host
​```

This is genuinely useful when working with services locked down behind a
bastion host or VPC — common in cloud infra setups.

## Takeaways

- SSH uses asymmetric crypto to establish a session, then symmetric encryption
  for speed during the actual session
- Key-based auth is more secure than passwords and avoids brute-force risk
- `~/.ssh/config` saves a lot of typing once you're managing multiple hosts
